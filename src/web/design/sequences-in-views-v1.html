Sequences folded into Views — option B
  • The Sequences nav tab is gone. Nav is now Views · Review · Configurations · Key Vault. The struck-through tab in the mockup is there only to show what was removed — it isn't part of the design.
  • The drawer became the library. Two tabs: Pipelines and Sequences. Both lists are draggable onto shelves, which is the honest model — a pipeline and a sequence are both "a thing you put on a shelf".
  • Editing happens in context. A sequence card's ⋯ menu gets Edit sequence…, opening a right-hand panel — the same slide-in pattern as the Configurations detail pane. The card being edited gets an accent rail so you never lose track of what the panel is pointed at.
  • Opening the editor auto-collapses the drawer. You don't need the library while editing, and three panels plus a board is too many.
  • Usage disclosure. The editor header states which views use this sequence, because in-context editing removes the "this is a shared object" signal the separate page gave you for free. Destructive edits warn against that list.
  • Step renaming lives here — the display name is the editable field, the real pipeline name sits under it in muted mono. This is what makes the verbose SB.ConfigRegistry.UserTypesMap · Deploy names fit on a card.
  • Pre-run inputs are a small table: key, type, default. Referenced by steps below.
  • Value passing is a binding chip per parameter, colour-coded by source — violet for a pre-run input, aqua for a previous step's output, slate for a literal. Click one to repoint it; the menu only offers steps earlier than the current one, so you can't build a cycle.
  • Broken bindings surface. Step 6 of ConfigRegistry Nuget SuperBuild references an input that no longer exists — the chip and the step border go amber. Try deleting the packageVersion input and watch step 2 break the same way.
  • Binding source colours are aliases of the existing identity hues (violet / aqua / slate) — no new colours, and no green or red, so invariant A2 holds.
