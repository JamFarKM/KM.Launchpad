The agent panel on the Review page — the design in short
  • Try the Connector switch, top right of the harness. It re-points this exact panel at BetBot, Claude via Anthropic, or GitHub Copilot with no other change — same layout, same badges, same citation behaviour. That uniformity is the point: "no seams" means the reviewer never has to know or care which provider is answering. See DESIGN_SPEC_CONNECTORS.md for how Settings configures it and how the server-side adapter per provider makes it possible.
  • The panel is a bottom dock, not a rail tab. The first version put chat on a second tab of the file-tree rail, so browsing files hid the conversation and vice versa. The file tree is needed constantly alongside the agent; the PR list on the far left isn't, so the dock sits under the diff and file tree only, and the tree stays visible and clickable the whole time the dock is open. Try the Dock switch, top left of the harness — collapsing it leaves a slim identity strip, never nothing, since an outage banner has to stay legible without expanding.
  • The landing state is its existing automated review, not an empty box. Findings first, chat below. The panel is useful before you type anything.
  • An answer is a list of segments, not one block with citations piled at the end. Each claim carries its own FROM DIFF / FROM PR DESC / INFERRED badge and its own citation chips, bundled directly under that claim's text — so which citation backs which sentence is never ambiguous. This is the most important element on the panel; see the note in my message.
  • Segments stream and badge one at a time, not the whole answer as a single growing string — see the Streaming state: the first claim is already badged while the second is still CHECKING SOURCES.
  • Inferences are boxed and hedged on their own segment, not the whole answer. BetBot cannot know why a human chose NOLOCK; the UI must not let it sound like it does, and it must not let one hedge read as if it applies to claims that were actually grounded in the diff.
  • A citation is a candidate inline comment. Every cited line gets a small persistent violet dot in the gutter — not just a hover highlight. Click it to open a threaded annotation right there in the diff, in-app only, never posted to Azure DevOps on its own. Cycle through open ones with the ‹ n of m › control under the dock header, and resolve them once addressed.
  • Read-only by default. Nothing reaches the PR unless you press Post as comment… — now available on each individual segment or annotation, not just the whole turn — which opens an editable sheet, posts under your name, and appends a — via BetBot attribution line you can delete.
  • Private to you, stated in the composer footer so nobody assumes teammates can see it. The same is true of inline annotations — they are not shared with other reviewers on this PR.
  • Staleness is surfaced. If the author pushes, an amber banner marks the thread as answered against an older commit, with a re-ask action.
  • A second entry point in the diff gutter — hovering a line gives the blue comment + and a violet ask, which opens or creates an annotation pre-scoped to that line.
  • Service-down is a real state, named, with the deployment to check. It's in a k8s cluster; it will be down sometimes.
  • The agent is a connector, not a hard-coded feature. The dock header, the outage copy, and every citation all read from whichever connector holds the PR questions capability in Settings › Connectors. Not connected is a designed state with exactly one action in it.
  • An agent that can't attest gets no badge it didn't earn. If a connector can't return structured output, the whole answer collapses to a single segment badged SOURCE NOT STATED with no citation strip — see the No structured output state. The one thing the UI must never do is infer a provenance value to fill the gap.
  • An outage doesn't blank the panel. Service down keeps the cached automated review on screen, labels it CACHED, and disables the composer with the reason stated — rather than replacing everything useful with an error.
  • The stale-commit banner is sticky. The panel auto-scrolls to the newest answer, so a notice that the thread is answering an old commit would otherwise scroll out of sight.
  • Violet is BetBot's identity hue — reusing --hue-violet. Not blue (A1 reserves it for actions) and not green or red (A2 reserves those for status). No new tokens.
