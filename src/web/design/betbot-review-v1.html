The agent panel on the Review page — the design in short
  • Try the Connector switch, top right of the harness. It re-points this exact panel at BetBot, Claude via Anthropic, or GitHub Copilot with no other change — same layout, same badges, same citation behaviour. That uniformity is the point: "no seams" means the reviewer never has to know or care which provider is answering. See DESIGN_SPEC_CONNECTORS.md for how Settings configures it and how the server-side adapter per provider makes it possible.
  • It's a tab on the existing right rail, not a fourth column or a floating widget. Files / BetBot. You never need the file tree and an answer at the same time, and the diff stays visible in the centre — which matters, because answers cite lines in it.
  • The landing state is its existing automated review, not an empty box. Findings first, chat below. The panel is useful before you type anything.
  • Every answer is labelled by where it came from. FROM DIFF (aqua) · FROM PR DESC (violet) · INFERRED (slate). This is the most important element on the panel — see the note in my message.
  • Inferences are boxed and hedged in the answer body, not just badged. BetBot cannot know why a human chose NOLOCK; the UI must not let it sound like it does.
  • Citations are clickable file:line chips that scroll and highlight the diff in violet — visibly different from add/remove green and red, so a citation is never mistaken for a change.
  • Read-only by default. Nothing reaches the PR unless you press Post as comment…, which opens an editable sheet, posts under your name, and appends a — via BetBot attribution line you can delete.
  • Private to you, stated in the composer footer so nobody assumes teammates can see it.
  • Staleness is surfaced. If the author pushes, an amber banner marks the thread as answered against an older commit, with a re-ask action.
  • A second entry point in the diff gutter — hovering a line gives the blue comment + and a violet ask, which opens the panel pre-scoped to that line.
  • Service-down is a real state, named, with the deployment to check. It's in a k8s cluster; it will be down sometimes.
  • The agent is a connector, not a hard-coded feature. The tab, the panel header and the outage copy all read from whichever connector holds the PR questions capability in Settings › Connectors. Not connected is a designed state with exactly one action in it.
  • An agent that can't attest gets no badge it didn't earn. If a connector can't return structured output, the badge reads UNVERIFIED SOURCE, the citation strip disappears, and the answer carries a note saying what's missing — see the No structured output state. The one thing the UI must never do is infer a provenance value to fill the gap.
  • Provenance is pending until the answer lands. While streaming, the badge reads CHECKING SOURCES rather than asserting a source in advance — see the Streaming state.
  • An outage doesn't blank the panel. Service down keeps the cached automated review on screen, labels it CACHED, and disables the composer with the reason stated — rather than replacing everything useful with an error.
  • The stale-commit banner is sticky. The panel auto-scrolls to the newest answer, so a notice that the thread is answering an old commit would otherwise scroll out of sight.
  • Violet is BetBot's identity hue — reusing --hue-violet. Not blue (A1 reserves it for actions) and not green or red (A2 reserves those for status). No new tokens.
