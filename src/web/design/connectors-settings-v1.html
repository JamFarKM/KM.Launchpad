Settings › Connectors — what the design is arguing
  • An agent is a connector, not a feature. No agent — BetBot or otherwise — is hard-coded. The Review page asks for whichever connector holds the PR-questions capability, so switching from BetBot to Anthropic directly, adding a second opinion from Copilot, or pointing a laptop at a local model is a settings change, never a code change.
  • Provider first, not URL first. Adding a connector starts with "which provider" — Anthropic, OpenAI, GitHub Copilot, or a Custom OpenAI-compatible endpoint — because the honest answer to "what do I need to paste" is different for each. An API key, an OAuth grant, and a URL-plus-token are three different mental models, and hiding that behind one generic form is what creates seams, not what removes them.
  • The seam moves to Launchpad's server, not away. "No seams" for the reviewer means the Review panel — badges, citations, streaming, the composer — is identical no matter which provider answers. That uniformity is bought by a server-side adapter per provider that speaks each one's native wire format and maps it to one canonical shape. See DESIGN_SPEC_CONNECTORS.md §5 for the adapter table.
  • Two different credential models, one write-only rule. Anthropic and OpenAI take a pasted API key; GitHub Copilot takes an OAuth grant instead, because Copilot access is tied to a licensed seat on a GitHub identity, not a bare secret you can copy around. Either way, nothing reaches this page a second time — a key becomes a ••••4f2a plate, an OAuth grant becomes an account chip with a Disconnect button. Neither can be read back out of the browser.
  • The browser never calls a provider. Every request — key-authenticated or OAuth-token- authenticated — goes out from the Launchpad server. That's what makes a write-only credential possible for either kind, and it's also why Copilot's OAuth redirect is a device-code flow shown inside this dialog rather than a pop-up: there is no browser-side callback to catch.
  • OpenAI needs no separate demo. Its editor is the Custom editor with the base URL fixed to api.openai.com/v1 — same header, same shape, so it reuses the Custom/OpenAI-compatible adapter verbatim. Anthropic and Copilot get dedicated states here because their auth genuinely differs (x-api-key, and OAuth, respectively); OpenAI does not.
  • Test before save, and name the failure. Every provider's Test connection calls that provider's own model-list endpoint. Each failure mode gets its own copy and its own next step — see the taxonomy in the spec. "Something went wrong" is never acceptable.
  • The model list is earned, not typed. Every provider's model dropdown is disabled until a successful test (or, for Copilot, a completed OAuth grant) populates it, so a typo in a model name can never be saved.
  • Capabilities are exclusive and visible, across providers. Exactly one connector answers PR questions, regardless of which provider it is. Assigning the capability to a different connector says which one it's taking it from, in the same sentence — see Capability contest and Three providers.
  • Colour follows the invariants. Blue is action only (A1). Green and red are status only (A2). The violet assigned badge marks whichever connector currently answers — it is not a provider identity colour, so it stays consistent even when the underlying provider changes. Providers are told apart by icon and name, not by hue, which keeps the palette from growing one colour per vendor.
  • Every state is designed, including the bad ones. Nothing connected, choosing a provider, an API key mid-add, an OAuth grant pending, an OAuth grant completed, a rejected key, healthy, two connectors competing for one capability, three heterogeneous providers coexisting, and healthy-but-now- unreachable.

Connectors

Agents that Launchpad can talk to — Anthropic, OpenAI, GitHub Copilot, or any OpenAI-compatible endpoint of your own. Connectors are yours — credentials are stored against your account, and questions you ask are attributed to you rather than to a shared service identity.
